# 谷子账本

直播间谷子（动漫周边盲盒）**储值记账工具**。单个 HTML 页面，零依赖、零构建、零服务器，直接托管在 GitHub Pages 上，手机浏览器打开即可用。

## 它解决什么问题

直播间的钱是"存着"的。顾客先存一笔钱，然后花这笔钱抽谷子；抽到的谷子如果选择寄售，卖出去的钱又回到他的账上。所以每个顾客在直播间都有一个**不断累积的余额**，而直播间每天都要说清楚：**我到底还欠每位顾客多少钱。**

工具只做三件事，但做到不会算错：

1. **记**——存入、消费、寄售售出，每笔都记在某个顾客名下；
2. **算**——余额 = 全部流水相加，永远等于账目算式的和；
3. **查**——按日/月/年看明细，并按天核对期初、发生、期末。

## 账目口径

余额只有一条公式：

```
当前余额 = Σ 存入 − Σ 消费 + Σ 寄售售出 ± 手动调整
```

对应你给的例子：

| 日期 | 事件 | 金额 | 余额 |
|---|---|---|---|
| 10-10 | 存入 | +30 | 30 |
| 10-11 | 抽到吧唧 | −15 | 15 |
| 10-11 | 吧唧寄售，定价 8 | 0 | 15 |
| 10-12 | 吧唧卖出 | +8 | **23** |

四个记账类型：

| 类型 | 说明 | 符号 |
|---|---|---|
| **存入** | 顾客预存进来的钱，记来源（微信/支付宝/现金） | + |
| **消费** | 抽谷子扣款，记商品名、制品类型、以及"寄走 / 寄售" | − |
| **寄售售出** | 挂着的谷子卖掉了，钱回到顾客账上 | + |
| **手动调整** | 补差、退单更正等，必须写原因 | ± |

**寄售是一条闭环**：消费时选"寄售"并填定价 → 这件谷子进入该顾客的「在售」货架 → 卖出时从货架点"卖出"，金额自动带出、自动入账、自动从货架移除。卖错了就作废那笔售出记录，谷子会自己回到在售。

## 功能

- **首页**：未兑付余额合计、每位顾客余额、按最近/余额/名称排序、搜索（名称/手机号/备注）
- **顾客详情**：
  - 顶部是一条**账目算式**，如 `+30 −15 +8 = 23`，一眼看清这个余额怎么来的（笔数多时自动折叠，可展开）
  - 累计存入 / 累计消费 / 寄售回款
  - 在售寄售货架
  - 明细时间轴，可按日 / 月 / 年分组，每行显示这笔发生后的余额
- **报表**：今日 / 本月 / 今年 / 全部；未兑付余额、净变动、存入、消费；**每日对账表**（期初 → 每日净变动 → 期末）
- **设置**：直播间名称、默认经手人、JSON 备份与恢复、CSV 导出、清空数据
- 记录可编辑、可作废（作废保留痕迹、不计入余额）、可删除

## 部署到 GitHub Pages（一次性，约 3 分钟）

1. 在 GitHub 新建一个仓库，例如 `guzi-ledger`，**Public**（私有仓库的 Pages 需要付费）。
2. 把本目录所有文件上传到仓库根目录（网页上传或 `git push` 均可）。确认根目录能看到 `index.html`。
3. 仓库 → **Settings → Pages** → Build and deployment
   - Source 选 **Deploy from a branch**
   - Branch 选 **main**，目录选 **/ (root)** → Save
4. 等 1～2 分钟，页面顶部会出现网址：
   `https://<你的用户名>.github.io/guzi-ledger/`
5. 手机浏览器打开这个网址，**建议添加到主屏幕**（iOS：分享 → 添加到主屏幕；安卓：菜单 → 添加到主屏幕），之后就像一个小 App。

第一次打开是空的。可以先点「载入示例数据看看效果」，熟悉后再「设置 → 清空全部数据」开始正式记账。

> 想先在自己电脑上试：直接双击 `index.html` 就能用（Chrome / Edge / Safari 均可）。

## 数据在哪、会不会丢

**数据存在浏览器本地（localStorage），不上传任何服务器。** 这是刻意选择：不需要服务器、不怕服务关停、断网也能记账。代价是：

- 换手机、换浏览器、清理浏览器数据 → 看不到旧账；
- **多人同时记账不会自动同步**（每台设备各记各的）。

因此请务必：

- **每天收播后点一次「设置 → 备份数据 → 导出」**，把 JSON 文件存到微信文件传输助手或网盘；
- 需要换设备时，在新设备上「导入」这个 JSON 即可完整还原；
- 首页在超过 7 天没备份时会自动提醒。

如果以后需要"多台设备实时同步 + 顾客自己扫码查余额"，就需要加后端（例如微信小程序 + 云开发），现有的记账逻辑可以原样搬过去。

## 本地开发

```bash
# 跑计算层单元测试
node --test test/core.test.js

# 起一个本地静态服务（可选，双击 index.html 也行）
python -m http.server 8765
```

截图 / 冒烟测试工具（需要本机有 Edge 或 Chrome）：

```bash
node tools/shoot.js "http://127.0.0.1:8765/index.html?demo=1" shots/home.png --w 390 --h 844
```

## 文件结构

```
index.html            入口，唯一页面（hash 路由）
assets/core.js        纯计算：金额、余额、算式、分组、每日对账、CSV（有单元测试）
assets/store.js       localStorage 持久化、增删改查、导入导出、示例数据
assets/app.js         界面与交互
assets/style.css      样式
test/core.test.js     20 项单元测试，覆盖业务口径
tools/shoot.js        无头浏览器截图 / 交互验证工具
```

技术约束：金额一律以「分」为整数存储和计算（不出现 0.1+0.2 的浮点误差）；时间以本地字符串 `YYYY-MM-DDTHH:mm` 存储（不涉及时区换算）。
